# Source and data provenance

The npm package contains reader/inspection code, four repacked generated palette datasets, and optional API dye-name lookup; the synthetic example files live in the repository and the demo only. It contains no raw game files, item tables, or private sample files. The palette generator layout and appearance policy are adapted from the MIT-licensed XIV Dye Tools source; [third-party notices](../THIRD_PARTY_NOTICES.md) retain the code notice separately from game-derived data rights. The maintainer selected MIT for the project's original library, demo and tooling code on 2026-10-20; the full [license](../LICENSE) is included in the package. As of 2026-10-23 the published versions are `xivcharakit@0.1.0-beta.1` (dist-tag `latest`), `0.1.0-beta.2` and `0.1.0-beta.3` (`next`). Only the library is publishable, while the workspace root and demo remain private. Game-derived data rights remain separate from code licensing.

Format references and source SHA-256 values are in [fixtures/manifest.json](../fixtures/manifest.json), with human-readable coverage in [compatibility.md](compatibility.md). Ktisis and Brio advertise GPL-3.0 repository licenses; Anamnesis's reviewed format files carry MIT notices. Those references inform field contracts; this does not relicense upstream material or establish a license for this project's code. Review notices if future implementation copies upstream code.

The [licensing review](licensing-review.md) verifies the three upstream license texts, records compatibility boundaries and documents the maintainer's subsequent MIT choice for original code.

The private sample folder is an opt-in test input, never a build input. The local corpus checker logs only aggregate counts. Synthetic fixtures use invented metadata and combinations of public format fields, without embedded images or copied character data. Original synthetic fixture contributions follow the selected project MIT license; producer exports retain their separate recorded permission. Shape compatibility is not producer-export verification. The [beta redistribution review](data-redistribution-review.md) records shipped data, applicable notices and the maintainer's 2026-10-21 decision to retain the bundled appearance palettes. Raw `human.cmp` distribution remains excluded.

Separately, on 2026-10-20 the maintainer supplied four default-setting exports from Anamnesis, Ktisis and Brio and confirmed ownership of the player character and permission for redistribution. Byte-identical copies are retained as test-only [producer fixtures](../fixtures/producer-exports/README.md), with hashes and the contributor permission statement in the manifest. These approved exports retain their supplied metadata and are not anonymized examples. They are excluded from the packed library and static demo. This permission does not select a general project/fixture license or settle game-derived data rights. Exact app versions, selective-export coverage and independent visual/control expectations remain open in [fixture validation](producer-fixture-validation.md).

## Palette baseline and regeneration

See also the independent [dye-name lookup](#dye-names-through-xivapi); its revision is not the palette's game version.

The planned extraction baseline remains XIV Dye Tools commit `b98c8584a85f5dc50b4b4392c508cc627ef004d6`, freshly verified as the public default-branch head on 2026-10-19. Its [palette index](https://github.com/FlashGalatine/xivdyetools/blob/b98c8584a85f5dc50b4b4392c508cc627ef004d6/packages/core/src/data/character_colors/index.json) SHA-256 is `026d62b28c72661cb4646fb7647dd1ba4ef6ea777f637ecdc6e8fc3e89366802`.

The index's `meta.version: 2.0.0` is a data schema version. The game revision is recorded separately as `gameVersion: "7.57"`, based on the maintainer's confirmation of the supplied matching binary below, rather than inferred from the index. [Palette metadata](../packages/chara/src/palettes/metadata.json) records all twelve source file byte hashes (for the baseline; a regeneration from another file empties that list unless `--keep-sources` is given) and four output hashes/counts. Downloaded sources were also checked against their pinned Git blob hashes. Creator inputs were checked for index order and RGB/hex agreement before dropping redundant RGB/index storage. Output hashes cover UTF-8 `JSON.stringify(parsed JSON)`, independently of whitespace. The dataset contains 13,248 creator colors and 12,960 shader colors, 26,208 total.

Creator palettes contain eyes, highlights, features, dark/light lips and face paint, plus tribe/gender skin and hair. The available shader baseline contains eyes, highlights, features, dark lips, and skin/hair. Missing shader light-lip/face-paint tables are not fabricated. The appearance policy compares both light and dark lips to the documented dark shader entry; this is an interpretation rule, separate from the provider's literal table lookup.

The adapted generator source is `packages/core/scripts/build-character-colors.ts`, SHA-256 `95c451282940489ddcb98a10d90efe7df1345db1b94a4e8c092deabb8de3206c` at the pinned commit. The appearance resolver and shader helper source hashes are respectively `41463ce6068f7cb7421b7f92c46fbb56b92396dfb603f33a3950a1facaf41cc0` and `0353afc0edaf853dc7139a263429317310f248bff4276cbd6524925d5e456e2d`.

`pnpm verify-palettes` requires exactly the four tables in the metadata, validates output hashes, table shapes/counts and independently reviewed sample colors, and prints the total it counted. Ordinary builds use the committed generated values and never discover a game installation or fetch data. To regenerate, supply a local extracted source explicitly:

```sh
pnpm exec tsx scripts/build-palettes.ts <explicit-human.cmp-path> --check
pnpm exec tsx scripts/build-palettes.ts <explicit-human.cmp-path> --dataset-version <new-version> [--game-version <verified-revision>] [--keep-sources]
pnpm verify-palettes
```

The generator checks file size/layout before reading, limits work to 16 MiB, writes fixed table/metadata paths, and records the source hash/byte length without its local path. `--check` changes no files: it compares the source hash and size and each table's hash and colour count with `metadata.json`, prints the differences, and exits non-zero when the file would change the committed palettes (so a patched `human.cmp` fails it by design). A write regeneration resets the metadata's `sources` list to empty, because tables regenerated from another game file no longer derive from the upstream JSON files it hashes; pass `--keep-sources` only when rewriting from the same inputs. `source` is kept (the field is not nullable): its repository and commit attribute the adapted layout code, but its `schemaVersion` is the upstream data schema of the baseline and is not updated, so after a regeneration from another game file it no longer describes the new tables. Review the complete data diff and update reviewed samples for an intentional dataset change. An explicit game-version argument is a maintainer claim requiring evidence; it is not inferred from the file. Synthetic binary tests establish shared/clan/gender offsets, interface/shader separation, and interleaved shader-hair extraction.

### Supplied-source verification — 2026-10-19

The maintainer supplied a real `human.cmp`: 186,752 bytes, SHA-256 `958e90e635b756fff3e1b9c08b7c33fb08708258eee913b8ab57672b67d5e025`. The check-mode generator produced the exact recorded artifact hashes/counts for all four tables (26,208 colors). A subsequent write-mode regeneration with the existing dataset version left every palette data file unchanged; only `generatedFrom` metadata was added. An independent hash check confirmed the source file remained unchanged.

This closes the real-source palette regeneration check for this binary and dataset. The raw file stays outside the repository/package, with `*.cmp` excluded from Git, and its local path is not recorded in metadata. The maintainer subsequently confirmed on 2026-10-19 that this exact file is from game version 7.57; `gameVersion` records that confirmation. The comparison covers the extracted palette regions, not the unused height/scale tables or every field in the binary, and does not settle redistribution rights.

## Dye names through XIVAPI

Dye names are requested from XIVAPI's Stain sheet only after an explicit host action. The resolver batches the selected IDs, requests chosen language fields, and retains canonical version/schema from each successful response. Successful complete responses can be cached; raw file values remain unchanged and available without network access. No dye-name table or full Stain CSV is bundled. See [API semantics](api.md#cached-dye-names) and the [dated feasibility probes](xivapi-dye-feasibility.md).

### Former English dye-name snapshot

The initial implementation bundled 126 English names derived from [xivapi/ffxiv-datamining's Stain.csv](https://raw.githubusercontent.com/xivapi/ffxiv-datamining/ab3b961d58988b493283eb9fd28cb930ea07b169/csv/en/Stain.csv). The source commit was `ab3b961d58988b493283eb9fd28cb930ea07b169`, CSV SHA-256 `0392c152bba1a3fbdeed89bc3e007e3b9e83d5a5ce618779f1a9439f009400bc`, and normalized name-object hash `bfbfa3d0be3fd48d183ae62f9fb0de5e2a21b37cab99e57e6f5ec32bdaddc4ef`. Its revision did not establish parity with the appearance palette's game version. These are historical provenance records, not current packaged metadata.

At the maintainer's request, the bundled table, synchronous lookup/metadata exports and CSV build/verify scripts were removed before first publication. Character palette tables remain unchanged and have their own provenance/rights disposition. Runtime lookup does not grant new rights to upstream material; Square Enix attribution and the separate notices remain.
